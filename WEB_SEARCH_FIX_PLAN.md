# Fix Broken Web Search Across GNOME Shell Extension and Qt Companion

## Context

Web search in Linux Island fails silently in the GNOME Shell extension and opens a blank companion window in the standalone Qt6 overlay:

1. **GNOME Shell extension URL validation always returns `false` in GJS (`extension/lib/searchEngines.js:20–31`)**: `isValidNavigationUrl(url)` calls `new URL(text)` inside `try { ... } catch (_) { return false; }`. SpiderMonkey/GJS has no global `URL` constructor (`typeof URL === 'undefined'`), so `new URL(text)` throws `ReferenceError: URL is not defined`, which is caught and converted into `false` for every URL (reproducible via `gjs -m tests/extension/search-engines.test.js`). Because both `SearchSection._submit()` (`extension/ui/searchView.js:121`) and `MediaView._openSearch(url)` (`extension/ui/mediaView.js:771`) return early when `!isValidNavigationUrl(url)`, pressing Enter or clicking `Search` in GNOME Shell does nothing.
2. **GNOME Shell search input & carousel interaction defects (`extension/ui/featureCarousel.js:297–325`, `extension/ui/searchView.js:51–145`)**:
   - `FeatureCarousel._isInteractiveControl(source)` checks `curr.classes.has(...)`, a property that only exists on the Node test mock `Actor`. Real GJS `St.Widget` instances use `curr.has_style_class_name(...)`, so `_isInteractiveControl` returns `false` for `linux-island__search-entry`, `linux-island__search-action`, and `linux-island__search-engine-btn` in GNOME Shell, allowing pointer motion inside the search input or buttons to trigger a carousel page swipe.
   - Clicking an engine chip (`Google`, `DuckDuckGo`, `Brave`, `Bing`) moves key focus onto the chip `St.Button` without returning focus to `this._entry`.
   - `SearchSection.focus()` does not focus `this._entry.clutter_text`, and `this._entry`'s `key-press-event` handler does not handle `KEY_Return` / `KEY_KP_Enter` / `KEY_ISO_Enter` if key focus sits on the outer `St.Entry`.
3. **Companion subprocess non-zero exit drops search (`extension/ui/mediaView.js:812–822`)**: If `linux-island-ui --companion <url>` spawns (`launchedCompanion = true`) but exits with a non-zero exit status (and was not replaced/terminated by a newer search), `wait_async` clears `_companionSubprocess` without falling back to `Gio.AppInfo.launch_default_for_uri(url, null)`.
4. **Standalone Qt6 overlay opens a blank `CompanionWindow` (`island-ui/qml/CompanionWindow.qml:13, 406–426`, `island-ui/qml/IslandWindow.qml:401–412`)**: When `companionLoader` in `IslandWindow.qml` loads `CompanionWindow.qml`, `WebEngineView.Component.onCompleted` runs before `Loader.onLoaded` assigns `item.initialUrl = targetUrl`. Because `windowRoot.initialUrl` is `""` during `Component.onCompleted` and `CompanionWindow.qml` has no `onInitialUrlChanged` handler, `webView.url` is never assigned in overlay mode.

## Approach

### Step 1: Replace `new URL()` with runtime-independent HTTP/HTTPS URL validation in `extension/lib/searchEngines.js`

- **Edit `extension/lib/searchEngines.js`**:
  - Replace `isValidNavigationUrl(url)` (`lines 20–31`) with a pure JavaScript parser that does not rely on `globalThis.URL` or `gi://` imports, ensuring identical execution under both GJS and Node.js:
    ```javascript
    export function isValidNavigationUrl(url) {
        if (typeof url !== 'string') return false;
        const text = url.trim();
        if (!text || /[\s\u0000-\u001F\u007F]/.test(text)) return false;
        const match = /^https?:\/\/([^/?#]+)(?:[/?#]|$)/i.exec(text);
        if (!match) return false;
        let authority = match[1];
        const atIdx = authority.lastIndexOf('@');
        if (atIdx !== -1) {
            authority = authority.slice(atIdx + 1);
        }
        if (!authority) return false;
        let host = authority;
        if (authority.startsWith('[')) {
            const closeIdx = authority.indexOf(']');
            if (closeIdx <= 1) return false;
            host = authority.slice(1, closeIdx);
            const rest = authority.slice(closeIdx + 1);
            if (rest && !/^:\d{1,5}$/.test(rest)) return false;
        } else {
            const colonIdx = authority.indexOf(':');
            if (colonIdx !== -1) {
                host = authority.slice(0, colonIdx);
                const port = authority.slice(colonIdx + 1);
                if (!/^\d{1,5}$/.test(port)) return false;
            }
        }
        return Boolean(host);
    }
    ```
- **Edit `tests/extension/search-engines.test.js`**:
  - Add boundary assertions for empty-host URLs (`https://`, `https:///path`, `http://:80`) and query URLs generated by `buildSearchUrl` (`isValidNavigationUrl(buildSearchUrl('brave', 'linux island')) === true`).
  - Verify with both `node tests/extension/search-engines.test.js` and `gjs -m tests/extension/search-engines.test.js`.

### Step 2: Fix GJS `St.Widget` class detection in `FeatureCarousel` and focus/Enter handling in `SearchSection`

- **Edit `extension/ui/featureCarousel.js`**:
  - Add helper method `_hasClass(actor, className)` on `FeatureCarousel`:
    ```javascript
    _hasClass(actor, className) {
        if (!actor) return false;
        if (typeof actor.has_style_class_name === 'function' && actor.has_style_class_name(className)) {
            return true;
        }
        return Boolean(actor.classes?.has?.(className));
    }
    ```
  - Update `_isInteractiveControl(source)` (`lines 305–323`) to check `this._hasClass(curr, ...)` for all interactive style classes (`linux-island__section-btn`, `linux-island__media-button`, `linux-island__quick-toggle`, `linux-island__player-badge`, `linux-island__progress-track`, `linux-island__progress-fill`, `linux-island__quota-action`, `linux-island__quota-row`, `linux-island__search-entry`, `linux-island__search-action`, `linux-island__search-engine-btn`, `linux-island__search-engine-btn--active`, `linux-island__carousel-dot`).
- **Edit `extension/ui/searchView.js`**:
  - In the engine button `'clicked'` handler (`lines 61–64`), call `this.focus()` after `this._onEngineChanged?.(engine.id)` so selecting an engine chip returns keyboard focus to the search entry.
  - In `this._entry.connect('key-press-event', ...)` (`lines 84–90`), check for Enter keys in addition to Escape:
    ```javascript
    this._entry.connect('key-press-event', (_actor, event) => {
        const sym = event.get_key_symbol();
        if (sym === Clutter.KEY_Escape) {
            this._onDismiss?.();
            return Clutter.EVENT_STOP;
        }
        if ((Clutter.KEY_Return !== undefined && sym === Clutter.KEY_Return) ||
            (Clutter.KEY_KP_Enter !== undefined && sym === Clutter.KEY_KP_Enter) ||
            (Clutter.KEY_ISO_Enter !== undefined && sym === Clutter.KEY_ISO_Enter)) {
            this._submit();
            return Clutter.EVENT_STOP;
        }
        return Clutter.EVENT_PROPAGATE;
    });
    ```
    (Because `_submit()` clears `this._entry` before invoking `this._onSearch(url)`, if both `clutter_text::activate` and `key-press-event` fire on a single key press, the second invocation sees `""` and is a no-op.)
  - In `focus()` (`lines 142–144`), focus both `this._entry` and `this._entry.clutter_text` when available:
    ```javascript
    focus() {
        this._entry?.grab_key_focus?.();
        this._entry?.clutter_text?.grab_key_focus?.();
    }
    ```
- **Edit `tests/extension/feature-carousel.test.js` and `tests/extension/capsule-rendering.test.js`**:
  - In `tests/extension/feature-carousel.test.js`, add a test verifying `_isInteractiveControl` returns `true` when an actor provides `has_style_class_name('linux-island__search-entry')` without a mock `.classes` `Set`.
  - In `tests/extension/capsule-rendering.test.js`, add `KEY_Return: 65293` to the `Clutter` mock and verify that pressing `KEY_Return` on `search._entry` submits the query and clicking an engine chip focuses `search._entry`.

### Step 3: Fall back to default browser when companion subprocess exits non-zero in `extension/ui/mediaView.js`

- **Edit `extension/ui/mediaView.js`**:
  - In `_openSearch(url)` (`lines 812–821`), inside `proc.wait_async(null, (_p, res) => { ... })`, after checking `if (this._companionSubprocess !== proc) return;`, inspect whether `proc` exited with a non-zero exit code:
    ```javascript
    proc.wait_async(null, (_p, res) => {
        try {
            proc.wait_finish(res);
        } catch (_) {}
        // The replaced process exits after the new one is already
        // installed; clearing state here would orphan it.
        if (this._companionSubprocess !== proc) return;
        this._companionSubprocess = null;
        this._onCompanionEnd?.();
        if (typeof proc.get_if_exited === 'function' && proc.get_if_exited() &&
            typeof proc.get_exit_status === 'function' && proc.get_exit_status() !== 0) {
            try {
                Gio?.AppInfo?.launch_default_for_uri(url, null);
            } catch (_) {}
        }
    });
    ```
- **Edit `tests/extension/capsule-rendering.test.js`**:
  - Add a test case where the companion subprocess exits with `get_if_exited: () => true` and `get_exit_status: () => 1`, asserting `launch_default_for_uri` is called with the search URL as fallback.

### Step 4: Fix `CompanionWindow.qml` initial URL loading in standalone Qt6 overlay mode

- **Edit `island-ui/qml/CompanionWindow.qml`**:
  - Add `property bool readyForNavigation: false` and an `onInitialUrlChanged` handler on `windowRoot` (`after line 15`):
    ```qml
    property bool readyForNavigation: false

    onInitialUrlChanged: {
        if (windowRoot.readyForNavigation && windowRoot.initialUrl && windowRoot.initialUrl.length > 0 &&
            webView.url.toString() !== windowRoot.initialUrl) {
            webView.url = windowRoot.initialUrl;
        }
    }
    ```
  - In `WebEngineView.Component.onCompleted` (`lines 423–426`), set `windowRoot.readyForNavigation = true;` right after cookie import finishes and before checking `if (windowRoot.initialUrl && windowRoot.initialUrl.length > 0)`:
    ```qml
    windowRoot.readyForNavigation = true;
    if (windowRoot.initialUrl && windowRoot.initialUrl.length > 0) {
        webView.url = windowRoot.initialUrl;
    }
    ```
- **Edit `island-ui/qml/SearchPage.qml`**:
  - On `searchField` (`lines 65–78`), add:
    ```qml
    onActiveFocusChanged: {
        if (activeFocus && Window.window) {
            Window.window.requestActivate();
        }
    }
    ```
    so clicking the search text field in standalone overlay mode always activates the window for keyboard input.

### Step 5: Build and install updated binaries and extension files

- Run `./packaging/dev/install-local.sh --build` to compile `build/dev`, update `~/.local/libexec/linux-island-ui` and `~/.local/libexec/linux-island-core`, and sync `extension/` to `~/.local/share/gnome-shell/extensions/linux-island@local`.

## Critical files & anchors

- `extension/lib/searchEngines.js:20–31` (`isValidNavigationUrl`) — Replaces `new URL()` (undefined in GJS) with a pure JS HTTP/HTTPS validator.
- `extension/ui/searchView.js:51–145` (`SearchSection._build`, `SearchSection.focus`) — Restores focus on engine chip click, handles `KEY_Return`/`KEY_KP_Enter`/`KEY_ISO_Enter`, and focuses `clutter_text`.
- `extension/ui/featureCarousel.js:297–325` (`FeatureCarousel._isInteractiveControl`) — Checks `has_style_class_name` on real GJS `St.Widget` actors in addition to mock `.classes`.
- `extension/ui/mediaView.js:767–830` (`MediaView._openSearch`) — Falls back to `Gio.AppInfo.launch_default_for_uri` if the companion subprocess exits with a non-zero status.
- `island-ui/qml/CompanionWindow.qml:13–23, 406–426` (`initialUrl`, `WebEngineView.Component.onCompleted`) — Navigates `webView.url` when `initialUrl` is assigned by `Loader.onLoaded` after `Component.onCompleted`.
